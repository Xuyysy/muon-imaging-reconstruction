## 1. 目标与不可变边界

在同一 GitHub 仓库中并行管理两种不同交付物：

1. **硕士学位论文线（`thesis/`）**：组织学位论文正文、章节、引用和经选择的证据引用。
2. **SCI 新算法线（`sci_method/`）**：为尚未确定的算法模型、期刊论文材料及其后续实验建立隔离空间。

现有 `B1/`、`muon_analysis/` 和 `B1/paper/` 是共同的历史与基线资产，不因双轨整理而移动、改名、覆盖或重新解释。新的算法数学模型、阈值、主评价指标和成功标准尚未确定；本设计只定义未来的数据和软件边界，不预设这些科研决定。

### 本轮已确定的原则

- Geant4、现有 POCA 实现、共享事件 CSV 和经审查的评价代码优先复用；原始数据只存一份并按只读方式打开。
- `B1/paper/` 是现有研究工作稿及其历史证据的保留区，不是本轮迁移目标，也不自动等同于学位论文。
- 真值掩膜、目标类别、真值面积、oracle Top-k 的 `k`、最终测试标签不得进入新方法的推断、参数选择、事件筛选或体素细分决策。它们只能在算法输出冻结后由评价侧使用。
- 开发、调参、冻结验证和最终未见测试必须有明确、可审计的阶段标签。已经查看或用于旧方法开发的旧场景，不因复制目录、改名或新建分支而成为新算法的未见测试集。
- 任何新实验输出均须有独立路径，并记录配置、随机数发生器/种子、输入哈希、代码版本、事件计数和来源说明。缺失的信息必须标记未知，不得猜测。

### 2.2 已发现的可复用代码候选与风险

本节是静态阅读得到的复用候选，不代表这些脚本已成为稳定公共 API，也不表示本轮准许直接依赖或修改它们。

| 候选 | 可复用能力 | 发现的限制/风险 | 建议边界 |
|---|---|---|---|
| `B1/src/EventAction.cc`、`B1/include/EventAction.hh` | 将四层首次击中按固定顺序记录；计算双线夹角、PoCA 和角度；CSV 同时包含击中坐标与派生 PoCA/角度列 | 当前每事件要求四层齐全；PoCA 是既有几何估计，不是真实散射点；输出默认路径为 `muon_analysis/muon_tracks.csv`，会创建/打开文件 | 共享作为既有数据生产链。新算法读取 CSV 时不回写；如未来新增仿真，须显式隔离输出路径并记录宏/随机流/二进制版本 |
| `muon_analysis/run_baseline_experiment.py` | `voxelize_poca()`、`u_target_mask()`、`evaluate_image()` 和图像/指标绘制；是固定体素 POCA 对照来源 | `evaluate_image()` 内部调用目标真值掩膜，并以真值像素数决定 Top-k；脚本含绝对机器路径，`main()` 会在固定 `baseline_results/` 写/覆盖 PNG、CSV、JSON、Markdown | 可作为历史基线和评价定义的查阅来源。新方法推断阶段不得调用含真值的评价函数；若未来要复用纯函数，先在另行批准的代码任务中做行为测试、消除路径/副作用并明确边界 |
| `muon_analysis/run_adaptive_voxel_experiment.py` | `imaging_edges()`、事件准备、固定细网格参考和现有自适应体素基线 | 同样是实验脚本而非稳定 API；导入 `run_baseline_experiment` 中常量/评价函数；实验参数与本研究方法绑定 | SCI 新算法的比较对象可以引用此既有实现；不可把旧算法公式直接当作新模型，也不得通过移动/重命名来制造不同方法的表象 |
| `muon_analysis/confidence_refinement.py` | 有效样本数、两半一致性和局部细化等已研究候选 | 导入多个实验脚本的参数/函数；关联现有开发与阴性/冻结验证证据，复用会携带既有选择与假设 | 仅作为旧候选或对照的来源；如 SCI 新模型要用其中机制，必须明确这是先验已知设计并重新界定其证据角色，不能宣称独立发现 |
| `muon_analysis/run_detector_resolution_robustness.py` | `recompute_from_noisy_hits()` 对击中坐标施加已选位置误差并重算轨迹特征 | 误差分布/误差注入方式是当前实验设定，不等于真实探测器完整误差预算；依赖旧脚本 | 可用于理解旧误差注入数据流，不自动作为未来误差模型的充分依据；共享原表必须只读，派生数据写入独立目录 |
| `muon_analysis/analysis.ipynb` | 交互式展示、历史处理步骤和现有结果导航 | Notebook 有隐式执行顺序、工作目录假设和存储输出；不适合作为模块 API 或新算法唯一复现入口 | 保留作为旧分析记录；SCI 新实验需有明确入口、配置和可审计输出，不把 Notebook 隐式状态当作正式实验记录 |

多项 runner/diagnostic 通过 `from run_... import ...` 直接相互导入；模块边界由历史实验逐步形成，存在较强耦合。多个脚本在 `main()` 中写入固定结果路径，重跑可能覆盖同名派生结果。它们的一些顶层常量还硬编码了本机绝对路径。因此，后续复用的首选次序为：

1. 按原样只读调用/引用已经确认无副作用的纯数据读取或几何/网格工具；
2. 对新研究实际需要的函数逐个审查其 import-time 行为、输入修改、输出路径和真值可见性；
3. 仅在单独批准后，以测试保护的方式建立明确的共享接口；不得在本轮顺手重构旧脚本或搬迁函数；
4. 对不能安全复用的能力先记录差异与风险，等待数学模型/方案冻结后再决定，不得复制一套含混的“公共代码”。

### 2.3 已观察到的数据输入/输出

`muon_analysis/muon_tracks.csv` 的现有列包含 `event`、四层 `up1/up2/down1/down2` 的 `x/y/z_mm`、`poca_x/y/z_mm` 以及 `theta_x/theta_y/theta_mrad`。四层击中是观测侧输入；PoCA 和角度是旧模拟程序已派生的字段。若未来的新模型从击中重估径迹，它应从击中字段重新计算所需观测量，不能把现成 PoCA 或目标真值默认为必要输入。

“输入事件数”与通过完整击中、筛选和成像范围门后实际参与计算的事件数含义不同，任何新记录都应分别报告：原始行数、有效四层轨迹数、算法筛选后数、落入视场数，以及最终参与重建数。当前 CSV 与 Geant4 随机流/精确运行命令的对应关系若无档案证明，须标记未知。

依赖方向约束：

- `B1/` 只负责已有模拟和已有事件导出，不依赖论文目录或 SCI Python 包。
- `muon_analysis/` 作为现有档案与共享输入提供者，不依赖 `thesis/` 或 `sci_method/`。
- `sci_method/src/` 允许依赖稳定的数据读取/几何元数据/绘图或评价工具，但不能由算法推断路径读取真值掩膜、oracle Top-k 计数或测试标签。
- 评价侧单向读取冻结的重建输出与真值；不得把评价输出回馈到模型参数、选择、阈值或细分决策。
- `thesis/` 和 `sci_method/paper/` 是写作消费者，引用共享证据与各自结果，不作为运行时依赖，不触发数据生成。

## 6. 实验数据隔离与防泄漏规则

### 阶段定义

| 阶段 | 允许做什么 | 禁止的证据表述 |
|---|---|---|
| 开发（development） | 探索特征、提出模型、做机制诊断、查看开发结果 | 不称独立验证或最终泛化测试 |
| 调参（tuning/selection） | 在预先指定的数据子集/划分上选参数、模型或阈值；保存所有尝试 | 不把被反复查看的数据再标为冻结验证/最终测试 |
| 冻结验证（frozen validation） | 在协议、代码提交、参数、主指标和成功标准冻结后，按一次性验证设计运行并报告 | 查看结果后改规则，再继续称同一数据为冻结验证 |
| 最终未见测试（final unseen test） | 仅在模型与分析方案冻结后由保管流程解封/运行；一次性报告主结果与全部预定义分层 | 不反复根据结果调整、筛选子场景、替换主指标或挑选“最好”的随机种子 |

每个新 study 在查看结果前，`protocol.md` 必须记录研究问题、主要比较方法、主指标、成功标准、事件数定义、筛选规则、场景划分、随机流计划、失败处理、排除规则和允许查看结果的人/时间。修改协议必须留版本和理由，标记为探索性偏离；不能静默覆盖旧计划。

### 旧数据与旧验证场景

- 旧 U/L/T/H、双块、不同材料/厚度等场景的历史角色，以原研究协议、论文和结果记录为准，原样保留。
- 即使旧研究将某场景称为 held-out/frozen，它在未来 SCI 新算法设计者已能查看现有代码、图表和结论后，也不能自动充当该新算法的“最终未见测试”。如新方法依据这些材料作出设计选择，应把对应数据列为开发/调参证据；确切角色按协议明确记录。
- 目录重排、复制、改名、重新生成同一事件子集或换一个绘图脚本，不会创造独立数据。
- 五次相关子抽样是从同一底层事件来源生成的子样本，不是五次独立 Geant4 物理重复；若子集有重叠，其相关性应进一步记录。统计分析不得以它们估计独立物理重复间方差。
- Python 子抽样随机种子与 Geant4 物理模拟随机种子是不同随机流。一个已记录的 NumPy seed 不能证明 Geant4 数据有独立物理 RNG 流；反之亦然。
- 真正的独立物理重复需有独立、可追溯的 Geant4 随机流/主种子、模拟命令/宏、Geant4/CLHEP 环境信息、目标/装置配置及输出哈希。多线程/多 stream 情况需记录相应流配置；记录不足时结论限定为单档案或相关重采样分析。

### 真值与 oracle 隔离

- 算法包的推断输入只包含观测侧数据（击中、由击中计算的轨迹/角度及允许的探测器元数据），不提供目标 mask、目标足迹面积、材料真值标签、理想散射点或最终测试标签。
- 真值对象由单独评价层在算法输出完成并冻结后载入。代码接口应做到权限/对象边界隔离，而不只依赖注释。
- `u_target_mask()` 或任何真值掩膜生成器只能被评价代码调用，不可从 `sci_method/src/` 导入。
- 等面积 oracle Top-k IoU 中，`k` 由真值目标面积决定，不能作部署时阈值、输出像素数、候选筛选、参数选择或细分决策；如报告，只能清楚标为带 oracle 面积信息的仿真评价指标，并同时提供不依赖该 oracle 的预定义指标/评价方式（具体选择待研究者冻结）。
- 任何以真值指导的 `greedy_with_truth`、真值掩膜阈值调优或测试集标签筛选均不得用于新方法推断或主方法选择。可作为事后上界/诊断时，必须放在显式标注的评价/诊断脚本中，和方法运行代码分开。

### 新实验记录契约

每个 `sci_method/studies/<study-id>/` 的实验结果需能回答：输入文件相对路径与 SHA-256、只读状态、输入行/事件数及各筛选后计数、宏与配置哈希、Geant4 构建/运行版本（如相关）、Python/依赖版本、代码提交 SHA、脚本/命令、物理 RNG 与分析 RNG 的算法/种子/流、协议版本、阶段标签、主指标和全部预定义对照。任何无法确认项写 `unknown` 和原因。

结果目录只允许新建唯一 run ID；如目标路径存在，运行器应拒绝覆盖或要求显式、可审计的新版本策略。不得让新方法脚本写入 `muon_analysis/*_results/` 或 `B1/paper/figures/`。共享原始 CSV 以只读模式打开；预处理结果为衍生品，需写入对应 study 的独立 `results/` 并记录父输入哈希。

## 7. 未来接口约定（模型未定，不是代码规格冻结）

以下仅约定安全边界和信息流。张量维度、分辨率、概率语义、损失函数、散射物理模型、阈值、权重、插值/正则化与目标输出定义均待模型研究和预注册设计决定。

### 观测输入概念契约

- 输入为事件表/批次：稳定事件 ID；四层击中坐标（mm）；必要时含观测侧探测器标识、测量不确定度与有效性标志。
- 可附来源元数据（输入哈希、单位、坐标约定、探测器/仿真配置版本）。这些 provenance 信息不作为可以泄漏标签的特征。
- 原 CSV 中预计算的 PoCA、散射角是旧程序派生列；是否允许作为新方法观测特征必须由方法方案明确决定。若目标是从原始击中端到端重建，必须只用击中重新计算，避免同时输入由同一观测确定的重复/未来标签。
- 真值掩膜、oracle 区域大小、场景名中编码的目标标签、材料类别和最终测试结果不属于推断输入。

### 算法输出概念契约

方法调用应表达为算法无关的形状，例如：

```text
reconstruct(observed_event_batch, frozen_method_config) -> reconstruction_result
```

`reconstruction_result` 至少携带坐标轴/单位、输出数组语义（待定义）、事件计数审计、拒绝原因计数和方法/配置版本。函数不接收真值对象、不写磁盘、不访问隐式全局路径、不选择评价标签。随机性若存在，须显式注入 RNG/seed，并在结果 provenance 中记录。具体 Python 类型/API 待数学模型和实现设计批准后再定。

评价流程另行表达为：

```text
evaluate(frozen_reconstruction_result, separately_loaded_truth, frozen_evaluation_protocol)
```

该边界保证真值只能影响评价输出，不能回流影响重建。评价协议还需区分 XY 投影和体积级 3D 结果；不得用 XY 图或 XY 指标表述为完整三维成像性能。

## 8. 尚未确定、必须由研究者后续决定的事项

- SCI 新算法解决的精确定义问题、物理/统计假设与数学推导。
- SCI 方法最终输入是原始四层击中，还是经过明确验证的观测侧派生特征；以及输出是散射强度体、物质/密度图还是其他量。
- 主要评价指标、成功标准、事件数预算、空间分辨率、接受率和运行时间约束。
- 开发/调参/冻结验证/最终未见测试场景、目标/材料/厚度范围，以及能否产生具有独立物理随机流的新 Geant4 数据。
- 独立物理重复数、随机流分配、Geant4/CLHEP 版本记录与数据归档方式。当前历史 CSV 缺少充分 RNG/精确命令溯源时，不得补猜。
- 真值 mask 的生成来源与 2D/3D 评价协议；不含 oracle 的部署时阈值/定位策略。
- 共享代码函数未来是否抽成公共模块，具体稳定 API、兼容性测试及维护者。
- 学位论文模板、学校格式规范、SCI 期刊与投稿时间、文本/图表复用及学位论文公开政策。
- 大型数据的版本化/存储方案；首选引用现有仓库数据，未来如超出 Git 合适范围再评估 LFS/对象存储，不在本设计中移动资料。

## 9. 分阶段实施方案与验收标准

各阶段均须保持 `B1/`、旧 `muon_analysis/`、`B1/paper/` 历史内容不变，采用独立提交；每个阶段完成后先审查，不自动推进下一阶段。

| 阶段 | 范围 | 验收标准 |
|---|---|---|
| 0. 架构文档审阅 | 本文与目录/数据边界设计 | 研究者审阅通过；分支提交可见；没有任何目录骨架、算法或旧文件改动 |
| 1. 学位论文资料登记 | 后续创建 `thesis/` 与模板/引用规则；对现有证据建立导航，不搬移原件 | 论文资料有来源/哈希/章节映射；`B1/paper/` 文件路径与内容不变；引用不复制原始数据 |
| 2. SCI 空间骨架和数据契约 | 后续创建 `sci_method/`, `paper/`, `studies/` 与只含边界的 README/schema 草案 | 无数学模型实现；只读数据输入约定明确；写入目录独立；oracle/真值字段不进入算法输入类型 |
| 3. 共享函数审查与接口测试 | 在单独批准任务中逐个做纯函数、副作用、路径、输入修改和真值访问检查 | 对调用依赖图和 I/O 有记录；已有结果复现/行为测试通过；没有未授权算法改变；不能证明安全的候选被排除 |
| 4. SCI 研究方案冻结 | 由研究者确定公式/假设/基线/主要指标/成功标准/场景分层/随机流与排除规则 | 运行前协议固定并版本化；真值与 oracle 隔离测试通过；开发与未见数据的访问计划冻结；用户明确批准开展实验 |
| 5. 开发与调参 | 仅在声明的开发/调参数据上实现和迭代新算法 | 所有尝试、配置、失败/阴性结果、种子、输入哈希、代码 SHA、事件计数都有记录；不宣称独立验证；旧档案未被覆盖 |
| 6. 冻结验证 | 冻结算法、参数、指标、阈值和代码后，在预定验证数据上一次性评估 | 冻结时间/提交、协议哈希和独立随机流/数据来源可查；偏离完整披露；看结果后不继续调参并称验证 |
| 7. 最终未见测试与写作 | 对算法完成独立外部/新生成数据评估后撰写 SCI 结果；学位论文综合完整研究 | 最终样本在冻结前未被用于选择；若不具备独立随机流或真正未见数据，降级结论而不伪称；两篇稿件所有共享资产均登记引用/来源 |

## 10. 风险登记

| 风险 | 证据/原因 | 设计缓解 |
|---|---|---|
| 误把开发/事后诊断当验证 | 现有论文/结果包含多轮方案、诊断和冻结场景 | 每个 study 固定阶段标签、协议日期和数据可见历史；历史角色保留，不因重排刷新 |
| Oracle 或真值泄漏 | 现有 `evaluate_image()` 依据真值掩膜设定 Top-k 数量；多个诊断含真值引导函数 | 算法 API 与 evaluator 进程/对象分离；接口测试禁止真值字段；Top-k 仅标 oracle 评价 |
| 伪独立重复 | 五次分析子抽样来自同一底层 CSV/事件池 | 将物理随机流与分析抽样 seed 分开；记录事件 ID 重叠；不将相关子样本当独立 Geant4 重复 |
| 旧脚本重跑覆盖历史结果 | 多个 `main()` 写固定 `*_results/` 路径并使用固定绝对根路径 | 新 runner 只写 study 唯一目录并拒绝覆盖；旧 runner 本轮不调用、不修改 |
| 共享函数引入隐藏耦合/副作用 | 脚本相互导入常量和函数，没有正式 API 层 | 新包不能依赖 Notebook 或任意 runner 的全局状态；先审查，再以独立兼容层/已批准提取处理 |
| PoCA/派生列被误作原始测量或真值 | CSV 同时包含击中坐标与由击中计算的 PoCA/角度 | schema 区分 observed/raw 与 derived；记录算法若用派生量及其生成版本；不能声称是直接探测器测量值 |
| 论文重复使用被误解为独立证据 | 两条线共享系统和部分数据/图是合理的，但容易重复计数或重复发表 | 建立 thesis/SCI evidence map；注明共有输入、图、代码提交和结果出处；检查期刊/学校政策 |
| 源数据 RNG/运行来源不完整 | 当前历史记录不一定包含 Geant4 seed 与精确执行命令 | 未知标未知；未来 run manifest 强制记录两套随机流及输入来源，缺项时限制结论强度 |

## 11. 本设计的完成边界

本文件只确定后续工作区的职责、依赖/数据边界、复用审查和验收路线。它**没有**建立 `thesis/` 或 `sci_method/` 目录，没有抽取/移动公共代码，没有设计或实现新数学模型，没有改变实验参数/结论，也没有运行任何物理实验。进入任一后续阶段前，须由研究者单独审查对应方案并明确批准。
