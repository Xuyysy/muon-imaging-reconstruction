# 四层探测器 CSV 的独立观测量审计计划

本轮只审计现有数据记录的信息结构，不设计新事件筛选或邻格借用规则，不重跑 Geant4，不改 CSV。所有 U/L/双铝块数据均已参与此前开发，属于事后证据盘点。

## 问题与来源

问题：现有四层输出中，是否真的存在可独立检验局部边界/事件质量的逐事件观测通道？读取 `B1/src/SteppingAction.cc`、`EventAction.cc`、`PrimaryGeneratorAction.cc` 的记录流程，以及三份已见开发场景 `muon_tracks.csv`、`muon_tracks_l_shape.csv`、`muon_tracks_double_block.csv`。另检查所有 `muon_tracks*.csv` 的表头是否一致；不把其多个文件当作独立物理流来估计成像性能。

## 预定核查

1. 逐文件校验列名与数量、行数、缺失/非有限数、事件编号重复、四层 z 坐标的唯一值，并记录 SHA-256。
2. 从四层击中坐标重新计算三个角度列，报告最大绝对差；容差解释必须考虑 CSV 的有限小数精度。POCA 三坐标的计算来源以 C++ 实现核对，不用不稳定的近平行线数值误差来证明它是“独立观测”。
3. 明确区分：四层位置击中、事件编号、由击中确定的散射角/POCA、外部指定的探测器误差标准差、未记录的独立通道（单侧冗余击中、逐层能量沉积、动量/能量测量、时间、探测效率等）。固定源能量是仿真设置，不是每条事件的实测动量。
4. 两层同侧直线恰好通过两点；“残差为零”是几何恒等式，不是轨迹可靠的证据。跨事件分半可构造统计量，但共享同一装置/事件池，不是额外探测器测量。

## 决策界限

若确无逐事件独立边界通道，只能说当前 CSV 不能支持“额外独立证据”的声称；不能说原始击中没有信息，也不能否定从不同事件的空间一致性或物理先验发展方法。下阶段优先在冻结前明确需要增加的探测信息、事件预算和真值隔离设计；不得在已见三场景上反复调参并称为独立验证。
